# Qualtrics survey build spec — Prolific reading-QA pilot

Build this survey manually in Qualtrics. Pilot: 3 reading conditions (`birds`, `birds_three`, `birds_repeat`), between-subjects, 10 shared MCQs.

## 0. Account / template

- Use NYU Qualtrics (`nyu.qualtrics.com`) so storage falls under NYU IRB.
- Create a blank survey: "Prolific Reading-QA Pilot".

## 1. Look-and-Feel → Header

Add these tags (loads jsPsych for the reading trial):

```html
<script src="https://unpkg.com/jspsych@7.3.4"></script>
<script src="https://unpkg.com/@jspsych/plugin-html-keyboard-response@1.1.3"></script>
```

Do **not** load `jspsych.css` — it overrides Qualtrics fonts and colours. The reading trial uses `font: inherit; color: inherit` to follow the survey theme instead.

## 2. Survey Flow

Top-to-bottom:

1. **Embedded Data block** — declare fields (leave values blank so Qualtrics picks up URL params):
   - `PROLIFIC_PID`
   - `STUDY_ID`
   - `SESSION_ID`
   - `assigned_doc` (filled by Prolific Taskflow URL param; must be one of `birds`, `birds_three`, `birds_repeat`)
   - `reading_rt` (filled by reading trial)
   - `reading_completed` (filled by reading trial)
2. **Branch** — IF `assigned_doc` not in {`birds`, `birds_three`, `birds_repeat`} → End of Survey (screen-out). Defensive; Taskflow always supplies it.
2. **Block: Consent**
3. **Branch** — IF consent != "I consent" → End of Survey (screen-out completion URL).
4. **Block: Instructions**
5. **Block: Reading trial**
6. **Block: MCQs**
7. **Block: Attention check + debrief**
8. **End of Survey** — redirect to Prolific completion URL.

## 3. Block: Consent

- Question 1 (Descriptive Text): paste contents of `consent.html` (generated by `clean_consent.py` from `consent_raw.html`). IRB protocol **FY2020-4512** ("Sources of Difficulty in Language Processing and Learning", PI Linzen). Use Qualtrics rich-text editor → Source view, paste HTML directly.
- Question 2 (Multiple Choice, single answer, force response): "Do you consent to participate?" Options: `I consent`, `I do not consent`.
- Question 3 (comprehension check, Multiple Choice, force response): one-question check on a key element of consent (e.g. "What can you do if you wish to stop the study?"). Branch failed answer to screen-out.

## 4. Block: Instructions

- Descriptive Text explaining task: read passage, time-limited, no copying, then answer 10 MCQs.
- No-copy attestation MC question (force response): "I agree not to copy, screenshot, or use external tools while completing this study." Options: `I agree` / `I do not agree`. Branch `I do not agree` → screen-out.

## 5. Block: Reading trial

- Single question, type **Text/Graphic (Descriptive Text)**.
- Paste contents of `qualtrics_reading_question.js` into the question's JavaScript pane. Replace the inlined `var STIMULI = {...}` block with the output of `python build_stimuli.py` (file `stimuli.js`).
- Block options: disable Back button; do not show Next button (the script clicks it programmatically after the timer expires).

## 6. Block: MCQs

- 10 questions, each **Multiple Choice (single answer)**.
- Auto-import instead of hand-entering: run `python build_qualtrics_import.py` → produces `qualtrics_mcq_import.txt` (Advanced Format). In the survey builder → Tools → Import/Export → Import Questions, upload that file. It creates the 10 MC questions with stable `QNN` export tags and a page break between each.
- After import (TXT can't set these): turn on **Force Response** per question (or block-level), and randomize choice order via Question behavior → Randomization → Randomize the order of choices.
- Choices carry no letter prefixes (order is randomized), so scoring keys off the **choice text** in the CSV export, not position. Correct answers stay in `birds_q.yaml`; set Qualtrics Scoring from them or score the export downstream.
- Add a question-level timer (Timing question, hidden) per page if you want per-question RT.

## 7. Block: Attention check + debrief

- One attention check ("Please select 'Strongly disagree' to confirm you are paying attention." Likert with that option.) Used post-hoc; do not screen-out on it so participants still get paid (Prolific policy).
- Debrief text describing the study purpose, contact info, IRB protocol number.

## 8. End of Survey settings

- Survey Options → End-of-Survey → Custom End of Survey Message → Redirect to a URL:
  - **Default end-of-survey (completed)**: `https://app.prolific.com/submissions/complete?cc=COMPLETION_CODE`
  - **Screen-out end-of-survey** (no-consent, failed comprehension/attestation): `https://app.prolific.com/submissions/complete?cc=SCREENOUT_CODE`
  - Both codes are obtained from the Prolific study setup page.

## 9. Prolific study setup

- In Prolific, create one study using **Taskflow → Multiple Conditions** to balance allocation across the 3 reading conditions.
- Get the survey's anonymous link (`https://nyu.qualtrics.com/jfe/form/SV_xxx`).
- Upload a Taskflow CSV with 3 rows (one per `assigned_doc`); leave per-cell N blank for even split:

  ```
  https://nyu.qualtrics.com/jfe/form/SV_xxx?assigned_doc=birds&PROLIFIC_PID={{%PROLIFIC_PID%}}&STUDY_ID={{%STUDY_ID%}}&SESSION_ID={{%SESSION_ID%}}
  https://nyu.qualtrics.com/jfe/form/SV_xxx?assigned_doc=birds_three&PROLIFIC_PID={{%PROLIFIC_PID%}}&STUDY_ID={{%STUDY_ID%}}&SESSION_ID={{%SESSION_ID%}}
  https://nyu.qualtrics.com/jfe/form/SV_xxx?assigned_doc=birds_repeat&PROLIFIC_PID={{%PROLIFIC_PID%}}&STUDY_ID={{%STUDY_ID%}}&SESSION_ID={{%SESSION_ID%}}
  ```

- Set single `COMPLETION_CODE` (Qualtrics default-end redirect) and a separate `SCREENOUT_CODE`.

## 10. Pre-launch checklist

- [ ] `build_stimuli.py` runs without validation errors after real text/questions filled in.
- [ ] `stimuli.js` blob pasted into reading-question JS pane.
- [ ] Prolific draft-preview link loads, `PROLIFIC_PID=PREVIEW` shows in Qualtrics response inspector.
- [ ] Manual end-to-end test by hand: passage renders (italics intact), timer runs, MCQs render, completion redirect fires.
- [ ] Chrome + Safari + Firefox: mouse-drag selection, right-click, Ctrl/Cmd+C all blocked on passage.
- [ ] Pilot 5 real Prolific participants before full launch.
